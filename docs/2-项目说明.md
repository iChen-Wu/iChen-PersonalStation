# 二、项目说明

## 一、它是什么

iChen 是一个**个人操作系统**：让 py、html 这类小文件程序有一个集成的中枢——发现、挂载、调度、
生命周期由系统统一承担。写一个 App 就是按规范放一个文件夹（`manifest.json` + `ui/` + `core.py`），
即写即用，类似 APK 的体验；桌面界面负责聚合与调度，程序常驻托盘。

智能体自我拓展只是平台开放的附带价值，不是刻意设计的目标。

## 四、关键机制

- **App 机制**：启动时递归扫描 `apps/`；含 `manifest.json` 的目录 = App；按 `app_id` 缓存模块、
  按文件 mtime 热重载；`core.run(params)` 在本地进程内调用（无沙箱）；后台 App 需实现
  `teardown()`。完整规格见 [3-App开发指南](3-App开发指南.md)。
- **前端挂载**：桌面读取 App 的 `ui/index.html`，经 iframe `srcdoc` 挂载并注入 `<base>`，
  postMessage 握手 / 主题同步 / 文件选择通道；共享样式由中枢注入（`shared/common/css/` 与
  `system/desktop/css/` 必须一致，有测试守护）。
- **实例保活与后台**：一个 App 打开 = 一个常驻 iframe 实例，切换只隐藏不销毁。Tab 栏的「后台」
  是运行实例列表（右键切前台/重启/终止）；「控制台 → 后台」是任务卡（运行时长、批量终止）。
- **自动化**：规则持久化 `data/automation.json`；触发器支持 打开 App / cron（5 字段）/
  中枢启动时；动作支持后台运行 App；cron 由惰性启动的守护线程按分钟轮询。
- **miniapp 打包分享**：App 右键导出 `.miniapp`（zip：App 文件 + requires 声明的 shared 整模块
  + 纯 Python 库；数据库 *.db 与 data/ 绝不进包）。导入时缺依赖自动补齐：shared 已有则跳过、
  二进制库转 pip 清单自动 `pip install --target data/pylibs`；同 id 引导更新式覆盖。
- **App 数据目录**：App 可写数据统一落 `data/appdata/<app_id>/`（core 读注入的全局
  `APP_DATA_DIR` 或调 `common.paths.app_data_dir(id)`）——覆盖导入只动程序目录，用户数据不受影响。
- **服务即 App**：没有独立服务类别，常驻端口 / 后台逻辑写成 `type: "service"` 的 App。
- **窗口**：无边框模式由设置开关控制（保存后重启生效）；拖动只走标题栏拖动区；
  托盘图标缺 pystray 时静默降级为关窗即退出。
- **配置位置**：`data/config/`（config.yaml、score_rules.json、class_datacenter.json、.env）、
  `data/local_config.json`（无边框等本机设置）、`data/automation.json`。

## 五、数据布局与红线

```
data/
├── db/
│   ├── gyun_data.db      # ★ GYun 共享业务库（SQLite）——最重要的文件
│   ├── gyun_data.db-wal / -shm   # SQLite WAL 与共享内存（最新写入可能在 -wal 里）
│   └── backups/          # 数据库备份
├── appdata/              # App 私有数据（data/appdata/<app_id>/）
├── pylibs/               # miniapp 第三方库落点
├── config/               # 中枢配置、积分规则、数据中心白名单、.env（密钥，不入库）
├── automation.json       # 自动化规则
└── local_config.json     # 本机设置
```

三版本数据边界：

| 版本 | data/ | 处置 |
|---|---|---|
| 开发版 | 开发测试数据 | 可随意重置，不承载真实业务 |
| **正式版 D:\iChen** | **真实业务库，日常数据全在这** | **最高保护级别** |
| 移动版 H:\iChen | 干净空库 | U 盘不存放唯一数据，有 D 盘镜像 |

红线：

1. 任何更新 / 同步 / 部署动作都不得覆盖正式版 `data/`（更新工具已硬编码保护）。
2. 不要用"拷贝一个空 db"处理报错——中枢找不到库时会**自动建空库**，表面正常启动、实则数据全空。
3. 不要在三个版本之间互拷 `data/`、`shared/GYun/data/`。
4. `.env` 含密钥，不进 git、不发给任何工具 / 文档。
5. U 盘不存唯一数据；每次更新后回写 D 盘镜像。

历史文件说明：`shared/GYun/data/runtime/gyun_data.db` 是 V3 路径迁移前的历史副本（约 2785 条），
新代码不读它；正式版 `data/db/gyun_data.db.empty_20261004` 是空库事故留存的空壳样本，勿删勿混用。
备份与恢复操作见 [1-开发流程](1-开发流程.md#5-数据备份与恢复)。
