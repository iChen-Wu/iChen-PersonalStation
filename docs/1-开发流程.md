# 一、开发流程与习惯

> 日常开发与发布的操作手册。项目定位与标准见 [2-项目说明](2-项目说明.md)、
> [3-App开发指南](3-App开发指南.md)；变更历史见 [开发记录](开发记录.md)。

## 1. 版本规则

- 一轮新需求开始时 **minor +1**（`x.y.0`，下一轮为 `3.2.0`）。
- 同一轮内每改动一次 **patch +0.0.1**（`3.2.0 → 3.2.1 → …`），直到该轮确认完成。
- 大版本更新 **major +1**。
- 版本号两处必须同时改：
  - `pyproject.toml` 的 `version`（不带 v）；
  - `system/kernel/base.py` 的 `APP_VERSION`（带 v，界面显示用）。
- 每次改动在《开发记录》追加一条：日期 — 版本 — 变更与原因。

## 2. 日常开发

```bash
python -m system.main                       # 启动开发版中枢（Python 3.14，D:\download\python）
python ../workbench/tools/run_tests.py      # 全量测试（全绿才收工，当前 149 项）
pip install -e .                            # 首次或环境变化后注册 GYun / BYu
```

- 工程台在仓库外 `../workbench/`（工作区级，多个 iChen 工程共用，不随仓库分发）：
  `tools/`（测试、更新、部署等脚本）、`experiments/`、`scripts/`、`temp/`。
- 工具脚本统一用 `find_project_root()` 自动发现项目根（system/main.py + pyproject.toml 双标记），
  可用环境变量 `ICHEN_PROJECT_ROOT` 覆盖；禁止写死 `parents[2]` 这类相对层级。

## 3. 开发习惯（硬性约定）

- **导入**：统一包绝对导入（`from common.paths import PROJECT_ROOT`），禁止 `sys.path` 技巧与
  相对导入；`apps/` 不得 import `system.*`（有依赖方向测试）。允许在中枢模块顶层用
  `try: from common.paths import … except: 相对定位` 的容错模式，以兼容移动版薄 shared 环境。
- **路径**：一律从 `common.paths` 取，禁止散落硬编码；`GYun.core.constants` 仅作兼容转发。
- **启动**：统一 `python -m 包.模块`；不直接跑 `.py`（App 的 `core.py` 自测除外）。
- **图标**：一律 SVG 文件，禁止 emoji / Unicode 字符当图标。
- **样式**：`shared/common/css/` 是公共样式唯一来源，`system/desktop/css/` 是运行副本，
  漂移由 `tests/test_css_sync.py` 守护。
- **界面文案与代码注释一律中文**；视觉走简约路线，不堆装饰元素。
- **后台资源**：App 起线程 / 端口 / 长连接必须实现 `teardown()`，由后台终止流程回收。
- **JS 注意**：`tests/test_shell_assets.py` 用自写 strip 器做括号配对检查，它不识别正则字面量——
  正则里避免出现 `//` 序列（如用 `/^https?:/i` 代替 `/^https?:\/\//i`），否则会被误判为行注释。
- **调试控制台**只在开发开关 `--debug` 下开启（F12 / 右键检查），正式入口不暴露。
- 全局对话框统一走 `iChen.Dialog`（alert / confirm / prompt；桌面端为 pywebview 原生对话框）。

## 4. 发布：三部署同步

中枢代码在开发版做好、测试全绿后，用工程台更新工具同步到两份部署。**工具只换中枢代码，
apps/ shared/ data/ runtime/ 硬编码永不触碰**（即使 `--apply`）。

| 同步 | 内容 |
|---|---|
| ✅ 会更新 | `system/`（逐文件镜像：新增/修改/删除）、`main.py`、`README.md` |
| 🚫 永不触碰 | `apps/`（各部署自己的 App）、`shared/`（分叉维护）、`data/`（业务数据）、`runtime/`（自带 Python） |

> 事故背景：V3 初期曾整目录覆盖正式版，中枢找不到业务库自动建了空库，数据看似"消失"
> （2026-10-04，已恢复）。此后更新只允许换代码。详见《开发记录》。

### 4.1 正式版 D:\iChen

```powershell
# 0. 测试全绿
python ../workbench/tools/run_tests.py

# 1. 更新前备份业务库（先从托盘完全退出中枢）
Copy-Item D:\iChen\data\db\gyun_data.db ("D:\iChen\data\db\gyun_data.db.backup_" + (Get-Date -Format yyyyMMdd_HHmmss))

# 2. 只比对（默认行为，不写入），核对变更清单
python ../workbench/tools/update_production.py

# 3. 确认后写入
python ../workbench/tools/update_production.py --apply
```

工具按 SHA-256 哈希比对，列出 新增 / 修改 / 删除；目标不像 iChen（缺 system/ 或 main.py）时
拒绝执行；写入后自动复核哈希，应显示"哈希复核全部一致"。

### 4.2 移动版 U 盘 H:\iChen

- U 盘在 **H:\\iChen**（2026-10 更换的新盘；旧 F 盘因间歇性写入损坏——整文件 null 化、
  目录链断裂——已淘汰）。
- 同一工具指定目标即可，流程与正式版相同：

```powershell
python ../workbench/tools/update_production.py H:\iChen          # 比对
python ../workbench/tools/update_production.py H:\iChen --apply  # 写入
```

- 写入后用 U 盘自带 Python 冒烟验证（embeddable 环境，路径随盘变）：

```powershell
$env:PYTHONPATH='H:\iChen\shared'
H:\iChen\runtime\python.exe -m compileall -q H:\iChen\system
H:\iChen\runtime\python.exe -c "import sys; sys.path.insert(0, r'H:\iChen'); import system.apphost.miniapp"
```

### 4.3 U 盘镜像备份 D:\workspace\portable_iChen

U 盘每次更新后，把整盘镜像回 D 盘备份（`/MIR` 会删除备份端多余文件，保持逐文件一致）：

```powershell
robocopy H:\iChen D:\workspace\portable_iChen /MIR /R:1 /W:1
# robocopy 返回码 < 8 即成功（1 = 有文件被复制）；完成后比对两边文件数
```

### 4.4 例外：工具覆盖不到的变更

- **改了 `shared/`**（GYun / BYu / common）：更新工具不同步。先在目标端备份对应文件，
  手工只拷贝**代码文件**（绝不拷贝任何 data/、*.db）；数据库结构变更必须配套迁移逻辑。
- **新增第三方依赖**：正式版用系统 Python，需在正式版环境手工 `pip install`；
  移动版禁止在 U 盘上直接跑 pip（小文件密集写入风险），用「D 盘 `pip --target` 暂存 →
  robocopy 顺序写入 → 导入验证」流程。
- miniapp 导入的第三方库不受此限：落 `data/pylibs`，经 `site.addsitedir` 免重启生效。

### 4.5 更新后验证

1. 启动目标部署：桌面正常、托盘在；
2. 打开 1~2 个业务 App，确认历史数据还在；
3. 涉及界面改动时切换一次深浅色主题；
4. 涉及后台服务时到「控制台 → 后台」确认服务能起、端口正常。

## 5. 数据备份与恢复

### 更新前必做

先从托盘**完全退出中枢**（保证 WAL 落盘），再复制业务库：

```powershell
Copy-Item D:\iChen\data\db\gyun_data.db ("D:\iChen\data\db\backups\gyun_data_" + (Get-Date -Format yyyyMMdd) + ".db")
```

中枢无法退出时，把 `gyun_data.db`、`gyun_data.db-wal`、`gyun_data.db-shm` 三个文件一起复制，
不要只拷主库（可能缺最新写入）。复制后核对文件大小不为 0。

### 节奏

- 每次正式版更新前：1 份带日期的备份；
- 大批量导入 / 改积分规则前后：各 1 份；
- 重要节点的备份另存到其他磁盘。

### 恢复

1. 退出中枢；
2. 备份复制回 `data/db/gyun_data.db`（当时连 WAL 一起备份的，三个文件一起还原）；
3. 重启，打开数据中心 / 积分管理核对条数与近期记录。
