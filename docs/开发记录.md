## 2026-10-26 — v3.3.2：修复设置页诊断/更新按钮无反应

- **现象**：设置里「打开日志目录 / 导出诊断包 / 查看最近日志 / 选择更新包」点击无任何反应。
- **根因**：v3.3.0 在 Python 侧加了 notify / get_recent_logs / open_log_folder /
  export_diagnostics / check_update_package / apply_update_package / update_app，
  但 `iChen.PyAPI` 是 bridge.js 里**手工维护的映射表**，新方法没有注册——
  前端调用拿到的是 `undefined(...)` 的 TypeError（Promise 静默拒绝，界面无提示）。
- **修复**：bridge.js 补齐上述 7 个映射（含未连接桥的兜底返回）。
- **防再犯**：新增 `tests/test_bridge_mapping.py`——反射 Api 全部公开方法，
  逐个检查 bridge.js 是否有 `api.xxx_yyy(` 调用；main.py 内部接线方法
  （托盘回调 / 窗口事件 / set_window 等 6 个）列入豁免表。
  该测试一上线就抓出了这 6 个历史遗漏（确认均为内部用途后豁免）。
- 测试：150 项全绿（新增 1 项）。

## 2026-10-26 — v3.3.1：修复折叠列表再展开导致当前 App 重启

- **现象**：列表折叠后再点同 Tab 展开，舞台上的 App 会重新加载（像被重启）。
- **根因**：`layoutStage()` 为了修正并排顺序，用 `appendChild` 把已有卡片重新挂回舞台。
  浏览器在 DOM 中移动 iframe 节点会**重新加载 iframe 文档**，于是 App 页面被强制重载、
  前端状态全部丢失。折叠展开会触发 `showForZone()` → `layoutStage()`，正好命中。
- **修复**：布局不再移动卡片节点，改用 CSS `order` 表达并排顺序——卡片 `order = 序号×2`，
  分栏缝 `order = 序号×2-1`；`.stage` 本身是 flex，`order` 只影响布局、不动 DOM。
  分栏缝的左右邻居也改为按 `order` 值查找（DOM 兄弟顺序已不代表视觉左右）。
  缝元素每次布局重建，属于新节点，移动它不会触发重载。
- 测试：149 项全绿。

## 2026-10-24 — v3.2.8：空白背景只写在占位卡内 · 并排窗口大小错乱修复

- **背景作用域修正**：舞台背景从 `.stage`（会沿 padding 缝透出底层色，看起来像"整窗变色"）
  改写到 `.stage-placeholder`（空白占位卡）上 —— 只在没有窗口的那张圆角卡内显示。
- **占位卡恢复实色**：去掉此前的 82% 透明 + 模糊（不再需要透舞台背景）。
- **并排大小错乱修复**：`layoutStage()` 原来只用 `card.before(divider)` 插缝，从不重排卡片
  本身，导致「先开 A 再开 B，收起 A 再点开 A」时 stageIds 顺序和 DOM 顺序错位（缝和
  flexGrow 都失效）。现按 stageIds 顺序把卡片 `appendChild` 回 stage，顺序与数组一致。
- **grow 不再会话内记忆**：去掉 growMem 读写（此前记住的像素比例在新会话会被错用为
  flex-grow 比例，导致一张卡过宽、另一张被挤窄），新建实例一律 `grow: 1` 等宽，拖缝
  再临时改。
- 测试：149 项全绿。

## 2026-10-24 — v3.2.5：单调度 / 多调度双入口（修正 v3.2.4 语义）

- v3.2.4 误做成「全局只能一个窗口」。实际要求是：**列表点击默认单调度，
  后台点击才叠多窗口**（仿 iPad：点 App 不会自己叠窗，从后台挑才会并排）。
- 舞台改回 `stageIds`（有序窗口列表），并恢复并排缝拖宽（宽度会话内记忆）。
- **分区列表点击 = 单调度**：舞台只留它，其余退回后台保活；
  它已是舞台唯一窗口时再点 = 收起。
- **后台调度器点击 = 多调度**：点击把实例加入舞台（已在本台点击则移除），
  可多个窗口并排；右键另有「单独显示 / 重启 / 终止」。
- 程序面板「切到前台」改为「放到舞台」（加到舞台，Tab 同步到该 App 所属分区）。
- 窗口是全局的：切分区 Tab 不改变舞台内容，只重排显示。
- 测试：149 项全绿。

## 2026-10-24 — v3.2.4：单前台调度（仿前台调度 / Stage Manager）

- **舞台改为单窗口**：同一时刻只呈现一个前台 App 卡片，其余实例一律退回后台保活
  （不销毁、不重载、状态保留）。原来「同分区多开自动分栏 + 拖缝调宽」随之移除。
- **列表点击 = 开关**：点未运行的 App → 打开并上前台；点已在前台的 → 收起回后台；
  点后台里的 → 调回前台。列表高亮跟随当前前台实例（`isForeground`）。
- **后台 Tab 变成调度器**：左列列出全部运行实例，标注「前台 / 后台」，前台排最前；
  点条目即可在前台↔后台之间切换，舞台即时响应，且不改变左侧列表所在视图。
- **分区记忆**：每个分区记住最后上过前台的 App，切 Tab 回来时自动恢复；没有则空占位卡。
- 卡片头「收起到后台」等价于 `hide()`；「关闭」仍走 teardown 回收。
- 测试：149 项全绿。
