接入 iChen

最快的方式：让 AI 帮你做 App
点下面按钮，复制一份完整开发规格，再加上你的一句话需求（例如「做一个记录每日饮水次数的小工具」）发给任意 AI， 它就能按规格把 App 文件直接生成好——把文件夹放进 apps/分区/，重开中枢即可使用，无需改动中枢本身。
这是什么
iChen 是一个 Windows 桌面中枢。中枢本身只保留两样东西：桌面（左侧分区 + 列表 + 工作区）和 调度（正在运行的 App 实例）。其余一切功能都以 App 的形式存在—— 一个 App 就是 apps/ 里的一个文件夹，可以随时新建、改名、搬移、删除，不需要安装。
界面怎么用
  • 最左侧竖栏：分区（Tab）。每个分区对应 apps/ 下的一个一级文件夹；最下面是「控制台」。
  • 列表区：当前分区里的分类与 App，点 App 即在右侧工作区打开；顶部标题可右键管理整个分区。
  • 保活：切换 App 或分区不会关闭它，只有在「控制台 → 调度」里点「终止」才真正结束。
  • 右键菜单：在列表里右键文件夹可新建 App / 文件夹、重命名、删除；在空白处右键可新建。
  • 系统托盘：关闭窗口只是收进托盘，进程和运行中的 App 继续运行；托盘菜单可「打开」或「退出」。
  • 设置：主题、Tab 栏位置、无边框窗口都在「控制台 → 设置」，部分设置重启后生效。
一个 App 由什么组成
中枢按目录扫描，只认文件、不认注册表：
文件夹里有判定说明
manifest.jsonAppApp 的名片，叶子节点，不再向下扫描
folder.json分区 / 分类提供显示名、图标、顺序，可继续向下嵌套
两个都没有普通文件夹兜底，按文件夹名显示，仍可向下扫描
App 的三个标准文件：manifest.json（名片，必有）、 ui/index.html（界面）、core.py（后端逻辑，可选）。 __pycache__ 和点开头的隐藏目录会被跳过；App 不能直接放在 apps/ 根层。
App 的类型
逻辑型有界面 + core.py。界面发消息，中枢在本地进程调用 run()。最常用。
纯界面型只有 ui/index.html，无后端。适合小工具、静态页面、小游戏。
URL 型type:"url"。界面就是一个网址，嵌在中枢内，或用系统浏览器打开。
后台服务型type:"service"。常驻端口 / 调度 / 长连接，必须实现 teardown()。
manifest.json 字段（App 名片）
字段必填说明
name是显示名，可中文
id是全局唯一标识，英文小写 + 点（如 demo.hello），通信 / 日志都用它，勿含中文
version否版本号，建议 x.y.z
description否一句话说明，显示在列表里
icon否图标路径（相对 App 目录），建议 SVG；缺省用默认图标
order否同层排序，小的在前；缺省按名称排
ui否界面路径，默认 ui/index.html，必须在 App 目录内
entry否逻辑入口，默认 core.py，必须在 App 目录内
type否logic / ui / url / service
url、containerURL 型网址；container 为 iframe（默认）或 external（系统浏览器）
requires否依赖声明：shared（shared/ 下模块名）+ py（pip 库），导出 miniapp 时按此打包依赖
分区 / 分类的 folder.json 更简单：name / icon / order / description， 均可选；不写也会以文件夹名正常显示。
界面如何调用后端（桥协议）
  • App 界面运行在独立 iframe 里，加载后中枢先注入共享样式并发握手消息 {"type":"ichen:bridge"}，收到即表示已接入。
  • 界面发 window.parent.postMessage({app, action, payload}, "*")，app 必须等于本 App 的 id。
  • 中枢调用 core.py 的 run({"action":..., "payload":...})，并把返回 dict 作为同构消息回执给界面。
  • 主题切换时收到 {"type":"ichen:theme", theme}，需设置 document.documentElement.dataset.theme。
  • 界面必须自包含：浏览器直接打开（独立模式）也要能用内置演示数据渲染。
中枢提供的样式基座
加载时中枢会注入共享样式（tokens.css + components.css），界面直接用 CSS 变量 （--color-bg / --color-text / --accent / --radius-md / --shadow-sm…） 和组件类（.btn / .btn-primary / .toast…），深浅主题自动跟随。 不要写死颜色值，也不要重复造同类组件样式。完整清单见下方规格原文第十二节。
core.py 与后台资源
  • 入口签名固定：def run(params: dict) -> dict，成功返回带 ok: true 的 dict，失败返回 {"ok": false, "error": "..."}。
  • 模块按 id 缓存，模块级状态在多次调用间存活；文件改动后下次调用自动热重载。
  • App 自身数据写 APP_DATA_DIR（core 里读注入的全局变量），或用户经文件通道选定的位置。
  • 在后台开了线程 / 端口 / 长连接时，实现可选的 teardown()：实例被终止或中枢退出时框架先调用它释放资源。
  • run() 同步执行、当前无超时，避免长阻塞。
选择本地文件 / 目录（文件通道）
iframe 里读不到本地路径。需要打开文件、选择目录或另存为时，向中枢发 {"type":"ichen:pick-file", app, requestId, mode, multiple, filter} （mode：open / folder / save； filter：image / json / all）， 系统对话框选出的绝对路径通过 ichen:pick-file-result 定向回执，再交给 core.py 真实读写。 用户取消不是错误；独立模式下该通道不可用，应提示「请在中枢内打开」，不得伪造成功。
数据与安全红线
  • 自身数据写中枢 data/appdata/<app_id>/（core 里读注入的 APP_DATA_DIR），或用户经文件通道选定的位置；不写系统目录、不访问其他 App。
  • entry / ui / icon 只能是 App 目录内的相对路径，绝对路径与 .. 一律拒绝。
  • 图标只用 SVG 文件，不用 emoji 当图标；界面不依赖外网资源。
  • 不在独立模式或未连接服务时伪造结果，要给明确提示。
从零到能用（5 步）
  1. 在某个分区下新建 App 文件夹（或在列表空白处右键 → 新建 App，由向导生成骨架）。
  2. 放入 manifest.json（写好 name 与唯一 id）与 icon.svg。
  3. 写 ui/index.html：先保证浏览器直接打开能渲染，再接入桥消息。
  4. 需要后端就加 core.py，按 action 分发、返回 dict；有后台资源就实现 teardown()。
  5. 重开中枢：列表里出现 App，点击打开联调；「控制台 → 调度」可查看与终止实例。
